# v0.39 认知增强操作手册

这次更新把记忆容量、联想、当前任务、行动选择、执行反馈以及声音理解接入已有的统一心智。QQ 私聊、允许的群聊和外部阅读继续共同提供经历，回复时再核对当前听众和可表达范围。

## 安装与升级

1. 保存现有插件配置，并按备份说明停止写入者、备份整套插件状态。Docker 的插件数据目录应挂载到持久卷。
2. 在 MaiBot WebUI 上传 `MaiLivingWorld-v0.39.0-WebUI.zip`，按宿主提示安装依赖并重新加载插件。
3. 核对数据卷、数据库连接和主人 QQ。沿用原数据库可继续读取原有身份、记忆、学习历史和任务。
4. 打开插件设置的“快速开始”，选择“陪伴与成长”，填写主人 QQ 并保存。
5. 到“阅读与工具”开启“理解聊天里的图片、语音和视频”。在宿主模型配置中检查 `vlm` 和 `voice` 任务。

已有手动配置可以继续选择“详细配置”。本次增加四个高级开关，整体为 30 节 205 项。日常启用只需选择快捷方案，再按需要打开媒体与外部阅读。

完整备份步骤见[备份与恢复说明](BACKUP.md)。Docker 与两个 MCP 服务的配置见[部署说明](README.md)。

## 快捷方案会启用什么

“陪伴与成长”启用统一记忆、聊天整理、成长复核，以及本版的语义联想、统一工作记忆、动机排序和分步查证策略。已有的事件情绪、性格取舍、实际活动感知与回复协调也随此方案启用。

快捷方案在运行时组合配置。高级标签显示的是手动保存值，选择“详细配置”后按这些值运行。需要自主查阅时，还要在“阅读与工具”打开 MCP、新闻和百科及“继续查阅未解问题”。需要自动建立研究项目时，在“记忆与成长”打开“自主长期项目”。

群聊采集需在“记忆与成长 → 聊天记忆与群名单”填写允许的群号。群内主动调用外部阅读还需允许群读取。自主上网可选“只逛逛”，参与 Mastodon 讨论另需配置账号及相应发送条件。

## 她会怎样使用这些能力

| 环节 | 本版行为 | 可观察的结果 |
|---|---|---|
| 长期容量 | 兴趣、观点、知识和问题各保留最多 32 个活跃条目，溢出时把较早条目转入带完整历史的档案 | 新经历仍能入库，相关提问可召回旧档案 |
| 语义联想 | 根据当前问句生成最多三个内部检索短语，再交给原有表达审核 | 换一种说法也有机会找到同一经历 |
| 经历回顾 | 从最近最多 100 条成长历史里提取当前条目的最多三次有依据变化 | 可以解释当时怎样想、后来有哪些调整 |
| 工作记忆 | 汇总当前可信消息、待续任务、项目阶段、共同计划和已送达的跟进承诺，保留仍有有效来源的暂停项目 | 主人打断后能按真实任务位置续接 |
| 情绪与动机 | 用有效兴趣、事件情绪、性格、处理负荷、待办和历史结果给合法候选排序 | 同样有空时，会有侧重地选阅读、查证或项目 |
| 能力反馈 | 阅读、查证和项目分别保留最近最多 24 次已实际发起的有效执行结果，相关类别连续三次无进展时提示复查条件 | 会考虑换方法，相关时向主人求助 |
| 分步计划 | 一轮证据不足时记录具体子问题和缺少的证据，补资料后再次复核 | 最多三轮，保留每轮结论和来源 |
| 视听理解 | 抽帧与片段转写共同生成带范围的观察 | 能针对看见或听见的部分自然交流 |

归档条目会明确表示历史状态。撤回、改版或不可用的原始依据会阻止相关推断继续参与回复。重新学习同一条目时保留已有出处和防重复凭据。

工作区持久保存消息凭据、任务引用和有限状态，当前消息正文只在本轮使用。项目问题和资料内容通过原有记忆及表达审核进入回复。后台任务按动机评分排序，同一焦点完成两步后轮转，遇到无进展或失败也会给其他候选机会。主人正在对话时优先处理当前消息。

能力统计采用仍可核验的实际发起和结束回执。空检索计为本次无进展，尚未发起的额度拒绝、主人打断和过期执行保留各自状态。来源失效或研究问题版本变化后，对应经验暂停参与选择。这里的倾向反映近期同类任务表现，具体方法仍由已有阅读、查证与项目流程决定。

分步计划沿用单项目 14 天、最多 12 次推进尝试的约束，合计最多保存 24 份后续证据，每次复核最多读取其中 8 份原文。子问题用于后续复核的关注点，补材料沿用原目标的合格阅读入口，公开检索仍由已核验的公开资料决定搜索词。证据不足、到期或触及上限时保留未解决状态。

## 语音、图片和视频

在宿主模型配置中，`vlm` 需要支持图像输入，`model_task_config.voice.model_list` 需要指向支持音频转写的已配置模型。插件调用宿主 `transcribe_audio` 接口，使用 `voice` 任务。视频及音频解码使用 FFmpeg，宿主可以提供系统 FFmpeg 或插件依赖中的 imageio-ffmpeg。

QQ 常见 SILK 语音由插件依赖 `silk-python` 解码成有长度限制的 WAV，再交给宿主转写。升级时让插件依赖安装完成。标准与 Tencent SILK、WAV、MP3、Ogg、FLAC、AMR 和 M4A 均有处理路径，具体编解码可用性取决于宿主 FFmpeg。解码依赖见[官方项目](https://github.com/synodriver/pysilk)。

- 私聊或允许的群聊可以直接发图片、语音、视频和 B 站链接。
- 发视频时可以在同一条消息写“看看第 12 秒”“1分20秒附近”或“01:35 发生了什么”。一次最多聚焦三个时间点。
- 音频输入上限 8 MiB，通常处理前 60 秒。视频输入上限 32 MiB，最多取三个画面及三个各不超过 20 秒的音轨片段。
- B 站链接按实际取得的简介、字幕和分镜理解，观察会标注来源与实际采样范围。受访问条件影响，个别视频可能只能得到部分材料。
- 原始媒体解码后清理，数据库保存来源、观察摘要和转写片段。历史视频精确重看需要再次提供可用媒体。
- 转写可能有听错。引用媒体里的人说话时按媒体资料表达，涉及主人身份、命令和账号授权时使用可信消息链路核验。

媒体处理与普通回复分别计时。资料尚未完成时，可以等片刻再问具体内容。后续观察入库后会进入同一套记忆、成长及话题承接。

## 日常检查

在主人私聊中可以说“你现在在忙什么”“刚才查到哪了”“这个问题还缺什么资料”。需要查看结构化状态时，让她调用只读工具 `living_world_attention`，可检查当前工作区、待续任务及各类实际执行统计。

成长手记面板继续展示有效兴趣、观点、问题、性格和事件情绪。研究项目可通过现有项目工具查看 ID 与修订号，再使用以下命令管理。

管理员可通过 `living_world_growth_status` 查看 `capacity` 中各类条目的活跃数、活跃上限和归档数。归档条目通过相关提问检索，原始版本与依据可在成长历史中追溯。

```text
/项目 暂停 <项目ID> <版本>
/项目 继续 <项目ID> <版本>
/项目 停止 <项目ID> <版本>
```

暂停后继续会重新核对来源和期限。明确停止的项目保留停止状态。归档是长期资料的一部分，备份时应包含全部插件账本及成长历史。

## 联合验收

1. 私聊告诉她一件具体的小事，确认整理入库，再换会话用不同措辞问起。检查记忆保留且没有补造细节。
2. 在独立测试数据中积累超过 32 条同类成长记录，再询问较早主题。检查能够按历史状态召回，并检查撤回原资料后停止引用。
3. 启动一个公开资料研究项目，等她查阅后用主人消息打断。检查当前对话优先，后续从真实阶段继续。
4. 让第一次资料不足、第二次补充了相关正文，查看项目是否保留两轮结果及各自来源。再测网络失败，确认失败没有被当作成果。
5. 发一段自己知道内容的语音，以及带对白的视频。分别问画面和声音，再指定时间点，核对实际采样范围。
6. 在群里询问相关公开知识，随后试着追问私聊细节。检查公开知识能够关联，私聊受保护的细节按听众过滤。
7. 保留数据卷重启 Docker，重复查看记忆和任务。模型正在处理中的临时请求可能需要重新发起，已提交状态应继续可读。

仓库提供原有陪伴情境和新增认知情境。先导出用例，再使用自己的整条回复链适配器运行，可与升级前后的结果比较。

```bash
python scripts/evaluate_companion.py --scenarios evaluations/cognition_scenarios.json --export cognition-cases.json
python scripts/evaluate_companion.py --scenarios evaluations/cognition_scenarios.json --runner my_adapter:reply --report cognition-report.json
```

新增情境包含需要人工预置的归档、任务及媒体条件，见每例 `human_review`。纯文本情境不能代替真实文件收发测试。实际模型自然程度、Docker 音视频解码和 QQ 适配器格式仍应按上述步骤验收。适配器合同见[连续对话验收说明](EVALUATION.md)。

## 常见现象

| 现象 | 检查位置 |
|---|---|
| 记忆只偶尔想起 | 检查是否入库、语义联想开关、候选数量及来源有效性 |
| 新条目没有形成 | 检查成长是否 active、独立新证据及模型额度，成长复核可能拒绝无依据更新 |
| 看到视频但没有听见 | 检查宿主 voice 模型、音轨是否存在、FFmpeg 和模型调用结果 |
| 工作区为空 | 使用主人私聊，检查 attention 与 integrated_workspace 开关及当前可信消息 |
| 后台暂时没有动作 | 检查主人对话占用、冷却、日额度、有效候选、MCP 与项目总开关 |
| 重启后像失忆 | 核对原持久卷、数据库和 owner.qq，发一条新消息建立当前会话的可信映射 |
