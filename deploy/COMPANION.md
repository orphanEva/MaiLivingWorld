# 长期伴侣模式与验收

## v0.36 重新形成喜好

启用“陪伴与成长”，在测试环境让一项已有兴趣的原始材料失效。给她新的相关材料，等独立的成长提案和复核完成，再查看管理员成长状态中的 `renewed_interests`。问她“你最近喜欢什么？”，核对当前倾向来自新材料。等她实际提过该材料，再问“你现在还喜欢这个吗？”。重启并保留数据卷后重复验证。

系统从零加上本次小幅变化，旧权重和旧来源留在历史中。第一次重建后，她只能谈当前有依据的倾向。之后再次累积新依据，才可以谈这段新经历中的变化。旧私密判断会继续受原来的表达边界约束。

重建时，本次输入不能包含旧兴趣的来源，候选依据也都必须尚未被成长消费。混入旧材料或没有实际变化时，该候选会被跳过；只有这类候选时，最近状态为 `interest_renewal_waiting`。关闭原始记忆读取器时保留原档案，待启用后重新核对。已完成的旧任务继续按原消费记录去重。当前能力适用于兴趣。

## v0.35 验收长期爱好

保留插件数据卷升级，启用“陪伴与成长”。选一个在成长面板里已经有 24 份依据的爱好，例如摄影。等新材料通过成长复核后，查看同一项的来源数量、修订和倾向。问她“你最近喜欢什么？”，等她实际提过有关的资料，再问“你现在还喜欢这个吗？”。重启后换一个主人私聊会话，也可以在话题有效期内继续追问。

每个爱好最多容纳 160 份依据。有条件时在测试库撤回第一份或最后一份材料，或把原文改成另一版，再问同一个问题。旧推断应暂停使用，其他兴趣继续按各自的依据回答。系统会保留原修订供核查。它尚不能仅凭剩余材料自动重算这个爱好。旧版本已完成的学习任务在升级时也不会自动重跑。

### v0.34.1 的两个验收场景（历史版本）

1. 在主人私聊里，让她实际提过一份同时关联两个兴趣的材料，再问“你现在还喜欢这个吗？”。即使回复只允许召回一条，也应先问清你指的是哪方面。当只关联一个兴趣时，可以谈该兴趣；要说过去和现在有变化，仍需有效历史。
2. 在测试数据中，让某个兴趣已有24份原始依据，再让同一批复核通过一份该兴趣的新依据和一条独立知识。检查知识入库、原兴趣保留全部来源，并在管理员成长状态中核对这轮跳过的兴趣数。如果只有超限的兴趣候选，任务完成时不会新增成长修订。

## v0.34 谈起兴趣与观点变化

启用“陪伴与成长”，通过真实资料和成长复核形成兴趣后，再遇到新的相关材料，偏好可能逐步调整。普通喜好回答可以使用最近20份成长历史中与当前兴趣匹配的一次变化，分别说明此前倾向和调整方向。首次形成兴趣、历史范围外的旧变化、撤回来源和管理员回滚都按实际可用记录处理。没有足够历史时，可以直接说还无法确定以前的倾向。

开启话题承接 `reference.enabled`，等她实际向主人提过相关资料后，可以问“你以前不是喜欢这个吗？”或“你现在还喜欢这个吗？”。观点方面可以问“你现在怎么看这件事？”、“你的看法变了吗？”或“你之前不是这么想的吗？”。系统会核对当前有效观点及来源，一个明确观点可接续，多条都可能对应时先确认对象。尚待核对的另一种解释会保留分歧标记。只有记录支持时才谈改变，形成改变的具体原因还需原始依据。

观点的独立依据复核和逐步调整使用已有的 `growth.review_beliefs` 开关，需启用后才能积累相应的分歧和修订记录。当前观点的承接也支持已有的普通成长记录。

公开见闻分享先用完整公开兴趣排序，再把有限候选交给模型。关闭模型选题时，全部候选都明确落在负向兴趣上，可以略过本轮素材。后台研究也会区分正负兴趣和强弱，未解问题仍可因自身研究需要继续推进。配置里的初始兴趣与旧认知兴趣继续提供弱参考。

## v0.33 喜好、选择与研究耐心

选择“陪伴与成长”，在主人私聊问“你最近喜欢什么？”、“有没有不喜欢的东西？”或“你有什么喜好？”。她会取仍有完整依据的自身兴趣，区分正向、负向和中性。缺少记录时可以说尚未形成明确偏好。来源材料可帮助解释具体内容，形成喜好的原因仍需依据。开启话题承接、实际聊过相关资料后，也可以短问“你为什么喜欢这个？”。

自主上网从全部有效兴趣提取固定公开话题，按偏好强弱轮换搜索，并在候选取舍时考虑负向偏好。等待工具或模型期间兴趣变化、依据撤回时，会停止旧轮选择。外发搜索词继续限定为公开词表，私人兴趣描述只在本地参与核验。

公开问题经过两个检索入口都没有新候选时，后续间隔按连续空轮数增加至原间隔的2倍、4倍等，上限取原间隔与24小时中的较大值。新问题版本可解除这项额外等待，实际读到新证据后恢复原间隔。工具失败按原失败退避处理，全局查阅间隔、日额度和租约仍须满足。状态随数据卷保存，重启和备份恢复后继续生效。

百科读取时的长修订编号作为出处元数据保留，正文仍按原表达规则检查。词条链接可能显示后续修订，回答应以当时实际保存的节选为据。

## v0.32 问起后来有没有弄明白

在“陪伴与成长”方案中打开话题承接 `reference.enabled`。等她实际向你提过一份材料后，可以问“之前那个问题后来弄明白了吗？”。她会根据仍有效的材料，寻找相关的一个成长问题，并一起回忆当前记录和原始依据。问题仍开放时可以谈目前的线索，已解决时可以解释材料支持的答案。旧记录可能只保留问题文字，因此仅有状态时要继续依据原文确认。多个相关问题都匹配时会先确定你指的是哪一个。

公开问题的后续查阅会避开刚读过、已送去复核的同版候选，给其他来源机会。搜索结果没有新材料时，可以保持开放状态，按原间隔再尝试。每轮最多两次检索、一次读取，失败和新版本允许重试。已读候选最多保留256个标记，24小时后可再次读取。网站只改正文而列表信息相同时，需要等下一次重读才能发现。

自主查到的百科节选也能在“你最近读到了什么？”中提起。它与新闻、网页共用真实阅读回执和表达审核，同一词条多个节选只展示其中一份。可在“继续查阅未解问题”开启时使用此功能，近期阅读回忆依赖 MCP、公开资料和工具观察记忆开关。查到的百科修订号随节选保存，链接指向词条页面，页面可能已有后续修订。

## v0.31 读完后的想法与继续研究

**顺着刚才那篇聊。** 先开启 `reference.enabled`，等她在主人私聊里实际提过一篇材料，再直接问“你觉得它哪里有意思？”、“你怎么看刚才读的？”或“你喜欢刚才那篇的什么？”。这些短追问会使用仍在时效内、能唯一确定的已提及来源。已有的相关兴趣、观点和有效事件感受会一并参与当前表达，感受仍由 `growth.emotional_episodes` 控制。她可以谈吸引她的细节、犹豫或不认同之处，也可以暂时没有看法。

这项承接核对绑定主人的原始私聊文本。转发、引语或其它账号说出同一句，不会替主人选定材料。一次聊了多篇、尚未真正发出相关内容，或原来源已撤回时，需要先明确是哪篇。更换会话或重启后仍按原时效和当前来源核验。

**让问题继续有下文。** 选择「陪伴与成长」，打开 **启用 MCP 工具**、**查新闻和百科** 和工具观察记忆，再开启原有 `mcp.research_enabled`。详细配置模式需开启 `growth.enabled`，并使用 `growth.mode = "active"` 和 `active` 统一心智。成长档案中的开放问题，只有全部依据仍有效且来自公开材料、话题词也能在原文中找到，才会进入公开查询。私人聊天里的姓名、经历和模型自行补出的关键词无法成为这条外查流程的依据。

后台先查新闻，缺少新的可读条目时可查百科。配置了 Brave Search 密钥时可查更广的网页。每轮最多两次检索并读取一个结果，沿用 `research_interval_seconds`、`research_daily_limit`、工具额度和成长模型预算。查到的内容先作为有出处的新观察，与原问题及旧依据一起交给成长提案和独立复核。证据足够时才可能解决原问题，仍不清楚时保留开放状态。关闭 `research_enabled` 可停止后续查阅，已有问题和材料继续按原规则回忆。

**把时间留给新内容。** 启用工具观察记忆的自主浏览，会在24小时内避开已成功读到正文且候选版本相同的新闻或网页。只读到摘要、读取失败、来源已撤回或候选内容更新时，仍可再次尝试。已读标记随原工具账本保存，重启后继续按真实经过时间计算。

## v0.30 聊聊近期的自主见闻

在下文联网设置中启用「只逛逛」及工具观察记忆，等她实际完成一次选读后，在主人私聊问“你最近逛到了什么？”或“最近有没有看到什么有意思的东西？”。这会优先找出最近七天内最多两条她自己选读的公开报道或网页，核对来源后交给当前回复。她可能只读到新闻摘要，表达时会保留这个范围。没有可用记录时，可以直接说近期还没有可聊的见闻。

只有绑定主人的本人私聊能触发这项近期活动回顾，转发和引用内容需要按原始发言核验。你明确让她查过的资料可以照常回忆，但自主见闻只取实际后台选读的记录。关闭「自主上网」会停止新一轮后台浏览。已学到的知识依各自来源和当前听众参与原有统一回忆。

Mastodon 会把候选机会留给新内容。自己发的帖子、已回应的原帖以及同版已读内容会被排除，对方新发的提及和编辑后的内容可再被看到。公开回复继续受每日次数、单帖去重及原帖核验约束。她可以选择读完就走。

## v0.29 自己挑想看的内容

完成「快速开始」并绑定主人后，到「阅读与工具 → MCP 工具与自主查阅」打开 **启用 MCP 工具** 和 **查新闻和百科**。先在主人私聊试一句“最近有什么科技新闻？挑一篇你有兴趣的，读完告诉我出处”。她可以先看标题列表，再按实际读到的报道或摘要回答。查背景时，可以让她另给维基百科的标题、来源和版本。可选的 Brave Search 让她也能搜索更广的网页。

把 **自主上网** 设为 **只逛逛** 后，后台会按已有兴趣，从游戏、天文、摄影等公开话题里挑方向。适合时，她会打开一条报道、搜索结果或公开讨论，也可以跳过整轮。轮次至少相隔三小时，每天最多四轮，还受原有工具和后台模型额度约束。启用工具观察记忆后，后续对话能引用有出处的实际阅读。

如果给她配置独立 Mastodon 账号，她还能看公开提及和相关讨论。选 **参与讨论** 并关闭安全演练（`general.dry_run`），才会以该账号实际回复。主人也可在 QQ 私聊直接发送纯文本 `公开回复 帖子编号 正文`。用空格分开指令、数字编号和正文，正文为 2–350 字符，不要附加图片、转发、链接或 @ 提及。自主和主人指定的回复共用额度，每个账号每天最多尝试两条，对同一原帖最多一次。

缺少账号、权限不足或回复结果需要核实时，她可以在主人私聊请你帮忙。处理后私聊发 `外站问题已处理`，即可清除待办，后续活动按原节奏继续。允许主动 QQ 联系的实例还会遵守既有的联系时机和频率设置。凭据请在容器设置，参考[部署步骤](README.md)。

## v0.28 聊天里的图片、视频和 B 站链接

1. 在 MaiBot 宿主的模型设置里，给 `vlm` 任务选择能接收图片的模型。使用云端模型时，你分享的图片或选出的帧会交给该提供方分析。
2. 在插件「快速开始」选择陪伴方案并绑定你的 QQ，再到「阅读与工具 → 连续阅读与学习」开启 **看聊天里的图片和视频**。使用详细配置时，对应字段为 `reading.chat_media_enabled = true`，并需启用主人绑定和 `active` 统一心智。主人私聊需允许采集本人消息。
3. 想在群聊使用，到「记忆与成长 → 聊天记忆与群名单」加入允许的群号，并确认 MaiBot 已能收到该群的消息。可以先用测试群发一张照片，再问“刚才那张照片里有什么？”。

| 你分享的内容 | 她实际得到的依据 |
|---|---|
| QQ 图片或截图 | 可访问的图片转换成适合模型观察的画面。宿主只给出媒体占位时，插件尝试通过 NapCat 取回这一条原消息并核对发件人与群归属。 |
| QQ 视频 | 从可读取的视频中最多抽取三个时刻的画面，可讨论看清的主体、动作和环境。对白与两个取样时刻之间的事情需另给线索。 |
| B 站链接或分享卡片 | 使用公开接口读链接指定的分 P，优先看官方分镜，缺少分镜时可对低清视频抽帧。取得公开字幕时只引用节选。 |
| 有链接资料、暂时取不到可辨认画面 | 用实际取得的字幕节选或标题简介回应。读取仍在进行、来源失效或视觉模型不可用时，可以说明“还没看清”。 |

例如你发一张窗台上的猫，再问“刚才那张图里，它在看哪里？”，她可以接着这一张的观察来聊。刚发过两段视频又问“刚才那个视频”时，需要先确定是哪一段。观察摘要存入已有记忆账本，后续按来源、内容和当前听众进行表达检查。「陪伴与成长」可继续从有效材料中学习。宿主消息记录和模型提供方的留存策略各自生效。

该开关独立于 CAP/Pixiv 网关和 `reading.enabled` 的作品连续阅读，默认关闭。适合先用小文件测试，图片上限 8 MiB，视频上限 32 MiB。读取和视觉调用均有限额，图片与视频二进制只用于本次取样或推理，插件的持久记忆保存简短观察。关闭开关会停止新的视觉读取；已保存的有效摘要仍按原有听众规则参与统一回忆。

**QQ 撤回有一个宿主限制。** 插件收到 NapCat 的好友或群撤回通知后，会清掉原消息的媒体观察，拦住迟到的识别结果和原消息重放。适配器需要允许传递好友或群撤回通知。部分版本用原消息 ID 同时标识消息和撤回，MaiBot 1.3.10 的默认 5 分钟去重可能先把撤回丢掉。这种情况下插件仍会保留观察，QQ 客户端显示的“已撤回”不能作为插件已删除记忆的凭据。

## v0.27 快速开始

在 MaiBot WebUI 的插件管理中打开 MaiLivingWorld 的配置页，第一栏选择「日常陪伴」或「陪伴与成长」，第二栏填写主人本人的 QQ 号，然后保存。管理员可在同一页改用其它方案。插件总开关在「运行与存储」。

- **日常陪伴** 启用主人私聊的伴侣风格、统一记忆表达、相处约定、忙碌或倾听指令和已投递话题的承接。可以私聊发 `/相处 记住 我们约好周末讨论这本小说`，再聊到同一件事。统一记忆表达可能调用模型。
- **陪伴与成长** 还会整理真实近况、事件和事实，调用模型提取与复核成长材料。首次安装时聊天来源为主人私聊。已有的额外私聊名单、群名单、模型额度、学习间隔继续生效。
- **详细配置** 按各分组原本保存的值运行。快捷方案使用「长期伴侣」私聊风格，并关闭专属的群聊身份提示；方案负责的开关以当前方案为准。MCP、外部资讯、主动联系、数据库连接与其它独立功能仍可自行配置。

如果宿主只显示原始 TOML，可在已有 `[owner]` 中设置 `setup_mode = "日常陪伴"` 或 `setup_mode = "陪伴与成长"`，并将 `qq` 填成自己的号码字符串后保存。切回 `setup_mode = "详细配置"` 即可恢复手动配置的运行方式。升级前已经设置好的用户可直接沿用「详细配置」。

## v0.26 记得跟主人提过什么

比如她从群里知道了一个摄影展。主人第一次私聊问起来，她可以直接介绍摄影展。如果同一段展览信息确实由她私聊发给过主人，下次话题相关时她可以自然接着讲。她只知道自己的发言，主人是否看过、是否认同，要听主人怎么说。

使用前先绑定唯一主人的 QQ，开启统一心智 `unified_mind.enabled = true` 与 `unified_mind.mode = "active"`。再将已有的 `reference.enabled` 设为 `true`。短指代仍使用 `reference.ttl_hours`；跨话题回顾自行保留最近30天内最多32份来源版本指纹。另开一个 QQ 私聊会话或重启容器后，使用原持久卷即可继续。

只有回复模型本轮可直接使用的原始来源、主人私聊的成功发送回执和可以唯一核对的完整内容同时具备时才登记。自由改写、草稿或只提到作品名时，她会按普通话题继续。群聊与其他人的私聊不会取得这段主人私聊的提及提示。主人可私聊发送 `/话题 清除` 清掉当前焦点和这些提及指纹；仅说“换个话题”则保留跨话题的提及记录。

```toml
enabled = true

[advice]

archive_enabled = true
```

**回复取舍。** 她会依据当前已核验的对话目的确定这轮主要在做什么：倾听、建议、纠正、轻松交流、回应喜讯、回答近期活动或普通交流。倾听时保留适用习惯，暂不追加泛化的建议说明与任务回告；明确询问活动或分享喜讯可以覆盖旧的倾听模式。身份与相处边界、来源表达限制、共读保护、事实修正和必要澄清始终保留。旧修复帮助避免再用错误依据，不要求每次重新道歉；暂不提及任务也不计作已回告、取消或安排了下一次发送。协调本身不额外调用模型，对话理解继续沿用原预算。

**事件感受。** 成长提案与独立复核可以保存对具体互动、观察或实际读取材料的有限反应，如好奇、欣赏、失望、牵挂、释然、满足和犹豫；同一对象允许有限混合感受。每项保留逐字证据、来源指纹和形成时间，仍属模型判断的暂时反应。最多同时保留16项，每批最多2项，每次需有近7天的新来源；强度按24小时半衰、最长7天，过弱或过期后停止作为当前感受使用。正常读取不会续期，重复来源与改名重放不能增加强度。来源缺失、变更或不允许向当前听众表达时不注入；主人自述的心情或偏好不单独变成她的感受，沉默与缺席不形成关系惩罚。感受不进入原始证据，也不虚构身体生活。

**记忆整理。** 这轮覆盖建议与自身表达修复两个账本。开启各自 `archive_enabled` 后，新增到64条活跃窗口上限时，将可归档的最旧项转入历史，保留原正文、来源、语义状态与版本；忘记后的最少指纹独立保留，不占活跃名额。仍有效的待发送建议草稿不会被抢先归档，若没有可归档位置则拒绝新增。相关旧项可以按词检索，空话题不会把整份归档塞回当前对话。其它账本不因此获得无限容量；历史与防重放记录仍会占用磁盘，需继续备份。

本版30节197字段、95文件包，沿用二十一SQLite库/82张MySQL表，无新增DDL。情绪保存在原成长状态与历史，归档标记保存在原建议/修复记录；旧v0.24数据可直接升级，旧记录不会被追溯制造情绪或自动归档。备份、恢复与真实效果验证见 [状态备份](BACKUP.md) 和 [连续对话验收](EVALUATION.md)。

## v0.23 有限的注意力与性格取舍

这一轮让“有自己的节奏”对应实际运行状态。她推进阅读、查阅或自己的项目后，可以暂缓新的后台探索；有过进展才增加负荷，时间经过后恢复。主人发消息仍优先正常回应，不把聊天次数、主人离开或打断当成惩罚原因，也不借此虚构吃饭、睡觉和身体疲惫。

在已有配置中合并字段，不要重复创建同名TOML节：

```toml
[attention]
enabled = true
activity_awareness = true   # 新字段默认 false

[growth]
enabled = true
mode = "active"
personality_tensions = true # 新字段默认 false
```

两项均需原有可信唯一主人与统一心智active。后台实际做什么仍由已有阅读、MCP、项目和注意力配置决定，这两个开关不会自动联网、下载、主动发消息或增加模型调用。没有可执行任务时不会为了显得忙碌而造出活动。

活动记录只说明真实阶段：正在推进、取得阶段进展、被打断或未成功，不代表读完整本书、研究已得结论或承诺已经完成。活动提示只在可信主人当前纯文本私聊的有限整句询问中使用，独立于 `dialogue_enabled`；当前识别“你在做什么”“你现在在做什么”“你在忙什么”“你现在在忙什么”“你刚才在做什么”“你刚才在忙什么”“刚才在忙什么”“你的进展怎么样”“你那边进展怎么样”，可带末尾标点。只说“进展怎么样”仍按普通话题和原有指代处理，不能擅自改成询问她的后台活动。仅参考30分钟内仍可核验的活动；没有记录、来源失效或无法核验时保留未知，不猜测。主人询问本身会让后台让位，所以刚才在推进的任务应说明为刚暂停，不能假称仍同时工作。具体作品、原文和成果仍通过原有工具与表达权限核验，不能把活动记录当作公开私人内容的通行证。

有限负荷复用 `attention.sqlite3` 的原控制状态。只有存在真实开始记录且获接受的后台进展才计入，每次增加0.25，每小时恢复0.25，达到0.75时暂缓新的后台行动；这些数值供检查调度，不应向聊天对象报数。开始记录来自实际发起的MCP调用或模型请求，取得调度名额、子模块配额不足或冷却等待本身不算尝试。同一完成回执重放、失败、旧租约和主人打断不加负荷。原有任务和游标保留，时间恢复后仍需满足已有额度、来源与权限才继续。重启不会清空负荷，时间回退不会凭空恢复。关闭新开关恢复原调度方式，不删除已有状态。这里是工程上的注意力调度，不是人的生理精力或情绪诊断。

`personality_tensions` 只读取已有的四项性格，最多选当前偏离中性最明显的两项取舍，不创建第二套人格或即时改动数值。好奇可以带来探索欲，也可能想展开旁枝；健谈愿意分享，也可能说得多；耐心愿意细讲，也需要顾及重点；谨慎会认真斟酌，也可能难以立即取舍。提示会要求她依据本轮需要收束这些倾向，例如明确要求简短时先说重点，需要充分说明时也不能用“性格如此”省略必要信息。变化继续由原有有据成长积累，初始中性状态不强行贴上缺点。

这些是回复风格和后台行为的有限约束，不保证每轮都呈现某个性格特征。不会故意制造事实错误、泄露秘密、拖延回答、发脾气或索要陪伴来展示缺点，也不会把表达上的犹豫记录为现实事件。已有观点分歧、主人明确更正和当前误会修复继续走各自原链路。普通回复中她曾经说过的任意错误，尚不具备通用的跨重启逐句追踪能力。

本版配置29节189字段、89文件发布包，仍为二十SQLite库/78张MySQL表，无新增DDL。沿用原持久卷可保留注意力状态、成长性格和历史；两个新开关属于私人配置，按 [状态备份](BACKUP.md) 另行保存。实际措辞、自然程度和工具延迟需在自己的Docker、QQ及所选模型中按 [连续对话验收](EVALUATION.md) 检查。

## v0.22 有依据地改观，回应眼前的好消息

她可以保留自己的暂时看法，遇到反例先承认分歧，再随着新依据逐渐调整。不是主人说一句“你必须同意我”就换立场，也不把“越来越确信”当作客观事实已经核实。沿用可信唯一主人和统一心智；在已有配置中合并以下字段，不要重复创建同名TOML节：

```toml
[growth]
enabled = true
mode = "active"
review_beliefs = true   # 新字段默认 false，需主动启用
```

保持 `[unified_mind] enabled=true, mode="active"`，并启用实际使用的原始记忆来源。`growth.mode="observe"` 仍只演练，不提交成长变化。复核使用原成长间隔，每批最多一次提案和一次独立复核，遵守共享模型预算及前台预留；不开启新联网权限或主动联系。

对相关旧观点，先取齐仍有效的原始证据，再连同新来源核对逐字引文、旧观点版本和新旧关系。首次出现修订或反例只保留候选；后续批次有新的独立依据支持同一候选、累计至少两条后才采用。重复输入和同来源的改写不能累加。原依据失效、缺失或无法在有界批次内完整提供时，不用新来源替它证明旧结论。新观点的初始信心有上限，后续每次调整也有上限；这些数值是程序的有限状态，不是事实正确的概率。

相关时可自然说“我目前更倾向……”“这点还没想定”。只有记录明确保存了观点调整，才能说明原先与现在的不同；形成原因只依据允许表达的旧新资料，不能编造“与你经历过某件事”。私聊、群聊仍共用同一个内部观点，表达继续核验所有原始来源和当前听众，不能把他人的私人经历换成她自己的公开故事。

“独立”目前按来源标识和规范化内容去重，不保证现实世界的消息彼此独立，也不保证资料本身真实。主题与候选匹配较保守，换一种说法可能暂不累计；不会为了表现有主见而强行改观。关闭 `review_beliefs` 使用原成长方式，已提交状态仍在原成长账本中；换会话或重启不会清空，来源失效后仍停止采用。

眼前的反应沿用现有 `[attention] enabled=true, dialogue_enabled=true`。主人先说“先听我说就好”，后来明确说“我考试通过了！”或“我终于拿到offer了，好开心啊”，当轮会提示接住具体好消息，避免继续按上一轮的难过来安慰。下一条没有明确喜讯时恢复原短时或长期沟通偏好；喜讯本身不保存为情绪、性格或已核实事件，零额外模型调用。

该识别限于160字内、最多三个完整子句的少量中文本人表达，不是通用情绪识别。“我拿到offer了，帮我想想办法”仍以建议为先；“我拿到offer了，不过我很担心”不能被强制庆祝。引用、第三人、假设、否定、图片/语音/转发或群聊不触发此主人私聊反应。未匹配时继续正常回复，不拒绝消息。实际措辞、自然程度与宿主回复模型仍有关，需按 [连续对话验收](EVALUATION.md) 在自己的部署中检查。

本版29节187字段、88文件发布包，沿用二十SQLite库/78张MySQL表。观点状态与改观历史复用 `growth.sqlite3`；当前喜讯枚举只留本轮内存，不新增账本。备份与恢复见 [状态备份](BACKUP.md)。

## v0.21 建议效果反馈

她可以记住先前建议是否真的发给了主人，以及主人后来有没有尝试、感觉是否有帮助。它不会自动执行建议、把沉默算作接受，也不会把一次效果反馈写成自己的性格或客观疗效。需要可信唯一主人和统一心智active，功能默认关闭：

```toml
[advice]
enabled = true
auto_feedback = true
interval_seconds = 600
max_daily_batches = 4
```

AI 在主人私聊中可用 `living_world_advice` 的 `sources` 找到本轮允许表达的原始资料，再用 `prepare` 准备有明确语境来源的建议。只有原样独立发送 `delivery_text` 并成功核验收件人和发送回执后，才记为已建议。引用、失败发送、换人/换消息后的迟到草稿无效；草稿十分钟过期，来源变化也会失效。来源提供讨论语境，不保证建议本身有效。此入口不需要新增MCP或联网权限，只有相关账本已启用并有有效记录时才可引用。

`list` 查看建议ID、版本及结果状态。主人可亲自发送完整私聊指令，模型工具不能代确认：

```text
/建议 尝试过 <建议ID> <版本>
/建议 没尝试 <建议ID> <版本>
/建议 有用 <建议ID> <版本>
/建议 没用 <建议ID> <版本>
/建议 停止 <建议ID> <版本>
/建议 忘记 <建议ID> <版本>
```

自然反馈可引用建议中唯一的具体片段，例如：`你说的“先把拍摄计划拆成三个小步骤”，我试了，没有帮上忙。` 必须明确对应唯一一条实际送达的建议；只说“那个没用”、谈论别人的经历、假设以后尝试或夸建议听起来不错，都不能自动确认效果。提取与独立复核最多两次模型调用，遵守共享额度和前台预留；关闭 `auto_feedback` 后仍可使用完整本人指令。

相关反馈经统一表达检查后参与后续回复；先前方法没用时提示承认并调整思路，不继续机械劝同一办法。结果始终标为主人自述，未尝试不等于失败；没有新反馈不自动更新。停止后不再参与建议，忘记清除该条建议与反馈正文并使排队/在途结果失效，旧输入和迟到回执不能复活它。原始来源和已有备份不因此删除。最多64条历史（含遗忘标记），反馈临时队列最多32条、最长7天、每条最多3次尝试；不会无限堆积重试。

## v0.19：记住相处方式，把答应的任务跟进到底

### 长期习惯

启用 `[habits] enabled=true`，保持可信唯一主人绑定及 `[unified_mind] enabled=true, mode="active"`。学习只看主人本人的私聊纯文本，不接受群友、转述、引用、媒体文字或关于别人偏好的描述。她自己的爱好仍属于成长系统；这里保存的是“与你怎样交流”。

例如“以后聊技术时，请解释详细一点”可经原话核对、独立复核后成为技术情境的篇幅默认。“刚才回复太长了”只先记录反馈，至少三条规范化后不同的消息跨24小时才可能形成习惯；重复发送同一句不能累加，沉默和情绪不会变成偏好。明确长期设置不能被普通反馈覆盖。日后说“这次简单说”优先于详细默认；这次需要建议时，也不会被旧的倾听偏好压住。

主人本人可直接私聊完整指令，无需模型判断：

```text
/习惯 设置 技术 长度 详细
/习惯 设置 倾诉 回应 倾听
/习惯 设置 默认 追问 少问
/习惯 清除 技术 长度
```

情境为 `默认/工作/技术/倾诉/兴趣`。`长度` 可选 `简短/适中/详细`，`回应` 可选 `倾听/建议/正常`，`追问` 可选 `少问/正常`。共15个固定槽位；当前情境覆盖默认情境的同一维度。必要解释、必要澄清及已确认相处边界始终优先。`living_world_habits` 在主人私聊中只读查看生效项、待确认反馈和设置说明。清除会推进水位，旧排队输入不能再次激活；重启、换会话后仍保留。

后台默认每5分钟至多一批、每日4批，每批最多两次共享模型调用，遵守前台预算预留。输入队列上限32条，临时全文最长7天；完成后只留输入、引文和去重指纹、时间与固定枚举，不保留原话全文。关闭 `learn_from_feedback` 停止自然语句学习，仍可使用完整设置/清除指令。

自然习惯学习采用保守的完整句证据。多个情境放在同一句、指代不明或否定范围不清时可能不保存；可分别说完整要求，或使用上面的设置指令，再通过只读工具确认。

### 承诺与结果回告

启用 `[followthrough] enabled=true`，并按实际需求启用已有MCP、提供者和操作权限。AI先经本插件真实创建支持的后台任务，再使用 `living_world_followthrough(action="watch", provider=..., task_id=...)` 起草跟进承诺。支持cap下载/PDF传输、Pixiv归档、动图预览和同步任务；不会把“以后帮你研究”之类无真实任务的话自动登记，也不会自主新增、取消或重试外部任务。

工具返回一条简短的 `delivery_text`，带“第 N 项下载/归档”等自然标记。需要作为**独立整条消息原样发送**，成功回执确认后才从草稿进入跟进。草稿十分钟失效；加前后缀、引用、否定、发送失败、群聊和无法核验收件人的消息均不计作承诺。这个明确约束用于避免把聊天草稿或旧消息错认成新承诺；宿主和模型是否能保留独立消息，需要实际验收。

跟进只查询原服务的真实任务状态，默认每5分钟至多一项、每日最多12次，另外占用已有MCP预算。后台任务完成不等于RPC成功；任务ID和完成状态须同时匹配。超时、断连、格式不明不会说成成功或失败，采用有上限的退避，14天或168次检查后标作“未能确认”。启用统一关注时，主人正在聊天会先让行；在途新消息、主人/配置/来源变化会使旧结果不再提交。

任务来源包含服务配置与指定环境凭据的不可逆指纹，不记录密钥原文。更换服务地址、访问令牌或配置后，旧任务不会自动认领到新服务。启用前没有来源证明的旧任务不能直接跟进；后台服务若在同一地址和令牌下换了数据，也应同步更改接入配置。环境值改变后，已有连接会拒绝继续使用，需更新配置或重启以重新连接。

有结果时，`living_world_followthrough(action="report")` 返回核验后的独立结果句；仍须成功发送才记为已回告。`action="list"` 查看状态。主动回告需统一心智active和原主动聊天功能，并遵守白名单、演练模式、安静时段、空闲时间、次数限制、暂停与拒绝联系。不开主动聊天时保留结果，下次主人私聊可通过工具回告。工具返回、宿主接受唤醒、草稿和发送失败均不等于已送达。

主人本人可发送 `/回告 取消 <id> <revision>` 停止这项跟进；此操作不取消外部正在运行的任务。取消不能由模型工具代为执行。

建议验收：先设置技术详细默认 → 换会话确认保留 → 本轮要求简短 → 清除后重启；再用一个真实小任务 → 成功送达承诺 → 查询到真实结果 → 成功回告。分别检查发送失败、同名任务、切换会话、换服务、暂停联系、群聊和陌生人不能错用主人状态。自动测试使用离线宿主/模型/服务替身及真实数据库；实际Docker/QQ/所选模型效果仍待部署后验收。

## v0.18：记错能改、问过会记得

在已有配置中启用 `[recollection] enabled=true`，保持唯一主人绑定及 `[unified_mind] enabled=true, mode="active"`。有待更正的记录才有可处理对象：`brain_memory`、`mind`、`bond` 或 `continuity` 需按实际使用启用。这个开关不会自动开通其它功能。

例如旧记录是“讨厌猫”，主人后来私聊说“纠正一下，我不是讨厌猫，只是对猫毛过敏”，后台可核对两处逐字原话、独立复核后保存更正。只有主人的明确自述、更改或澄清会参与；转发、引述、第三人描述、含糊的“终于结束了”、身份变更要求不能据此改记忆。普通群友不能更正主人的档案。本轮聊天仍正常回应，更正是否落盘可由只读工具检查，不能在处理完成前声称已经记好了。

原始账本保留；更正只覆盖唯一匹配的旧原话片段，其它独立内容保留。一条原记录最多保留4处互不重叠的更正，先改面试日期、再改猫毛过敏不会让前一次更正丢失；跨度相交但指代不一致时不自动覆盖。以后统一回忆、表达复核和成长使用有效版本，依赖旧来源指纹的结论停止使用。原来源被改版、删除、停用或关闭相应来源功能后，该更正失效；不会拿旧副本代替已不存在的来源。对同一旧片段再次明确更正时，新条目接替前一条，审计保留。更正依然标作主人自述，不因多次复述变成独立证实，也不会把主人的喜好变成她自己的兴趣。

主人私聊可让她使用 `living_world_recollection` 查看当前更正、逐字依据、是否有效以及排队数量；每页20条，可用 `offset` 翻页。要撤回其中一条，主人本人发送完整指令 `/更正 撤回 <id> <revision>`。撤回恢复该片段当前原始内容，其它独立更正保留，不复活同片段更早的更正；这是撤回更正，不是删除原始记忆。原始遗忘仍使用对应账本已有的遗忘方式。切换会话与重启均保留状态。

启用后，回忆会扩展少量固定相关词并按相关性排序；涉及时间时只利用明确事件时间，不把记录更新时间当成事情发生时间。这是轻量检索改进，不是完整语义搜索，也不会自动将模糊代词绑定到某个事件。

她真实发送给主人的问题，只有成功回执、机器人账号和主人私聊目标均核验通过，且问题中有匹配的具体话题词，才记作“问过”。出站正文不保存，只保留消息指纹和话题版本；失败、草稿、群聊、普通陈述和无法核实目标的回执不计。默认24小时内，同一版本的追问会产生减少重复的表达提示；主人主动聊起仍可正常回应，新来源版本使旧回执失效。这降低重复追问，不能保证模型永不重复，也不把发过问题推断成主人已回答。

后台每批至多两次模型调用，默认5分钟间隔、每日6批。输入队列最多32条、临时文字最长保存7天；成功、过期或终止后清除临时全文，必要逐字更正依据和去重审计仍保留。最多128条尚未撤回或被新更正替换的条目，达到上限不自动删除旧记录。发送明细最多256条，防重放回执指纹保留。

`unified_mind.reserved_reply_calls` 默认12：总预算60时，后台最多使用其中48次，剩余部分留给前台内部理解和表达判断；总额度不增加，重启不重置。前台已经消耗的调用也计入同一总额。若总额不大于预留值，后台模型工作会等待，设为0可沿用旧预算方式。预留覆盖统一心智、成长、近况、更正和阅读所用的共享预算；不控制宿主最终回复生成，也不代表回复时延保证。

验收可以依次尝试：记录原说法 → 明确纠正 → 确认只读工具显示生效 → 重启和换会话再问 → 再次纠正或撤回 → 检查其它独立事实仍保留。另验证同一近况提问发送失败不计、成功后减少重问、含糊的“结束了”不会擅自结案。多轮合成情境与真实部署适配器使用方式见 [连续对话验收](EVALUATION.md)。本项目测试使用合成内容；实际 QQ、Docker 和你选用的模型仍需部署后验收。

## v0.17：持续关注与自然接话

在现有配置中加 `[attention] enabled=true`，并保持 `[unified_mind] enabled=true, mode="active"`。默认不开启，也不会自动打开阅读、MCP、成长、主动联系或下载权限。

统一关注从**已开启的Pixiv文字阅读**与**成长系统中有有效来源的未解问题**里，每轮选择一个推进。好奇倾向和当前兴趣影响选题顺序，当前关注优先延续；连续两次成功后换另一个候选，失败或暂时不能推进时先轮到其它候选。这里的研究仍仅使用已有Pixiv缓存检索与详情，不是全网搜索或自动寻找新书。来源失效、被停用或已完成的事项退出候选。

可信主人私聊到来后，默认90秒优先对话；媒体、命令和长消息也可作为活动信号，但不因此被当作可学习的文字或新的授权。阅读/查阅在途任务会失效，不能继续下一步或把失效结果当成进展；已有已提交进度保留。后台每轮至多一个行动，默认间隔5分钟、每日12次尝试，并继续遵守阅读与MCP原有配额。重启不会重置额度或忘掉待续关注。其它记忆整理与成长维护仍使用原有调度。

`dialogue_enabled=true` 时，符合倾诉、求建议、纠正理解或轻松聊天线索的当前主人纯文本，可做一次短时语境判断。普通问候/确认/无关知识问句跳过，明确短句零模型；其余每条当前消息最多一次共享预算调用，最多等待8秒，不重试。不确定、预算不足或来源变化时回到现有表达，不把推测写成长久性格。固定提示不会向回复模型转述分类证据原文。

例如先说“我只是想吐槽一下今天的事，不用帮我分析原因”，再说“不过你帮我想想明天怎么安排”，可以从倾听转为建议；“你理解错了，我说的是安排太满，不是讨厌工作”，会提示回复模型先修正这次理解，避免泛泛道歉或继续沿用误解。纠正模式在下一条新消息到达时清除，其他模式有短时有效期。`dialogue_enabled=false` 停止本模块的对话模式注入，后台关注仍可继续；`enabled=false` 则恢复原有阅读/研究调度。

当前表达优先级为：本轮明确要求或核验通过的分类，然后最新有效的短时偏好，最后正常接话。不会同时叠加互相矛盾的倾听与建议提示。群聊沿用统一记忆和场合判断，不注入主人私聊的沟通模式。

可在主人私聊中让她调用只读 `living_world_attention`，或在成长手记的「此刻的关注」查看当前状态、待续活动类型、上次后台结果。面板不展示原话、来源ID和内部任务参数。注意力账本只存消息指纹、枚举状态和任务引用，不增加一份聊天原文副本；沟通模式不是事实纠错工具，长期近况仍通过原有证据流程更新。

这版使**插件内部**的旧回复背景和后台工作在新消息后失效；没有新增宿主消息合并器，也不能撤回宿主已经生成或发送的普通回复。她的阅读与研究必须有真实进度，不能据此编造看过的内容、离线生活或持续隐藏思考。

多轮验收建议：

1. 开启一项文字阅读或准备有来源的未解问题，观察后台只推进一项；私聊后暂停，安静一段时间后继续。
2. 在工具或文字理解请求等待时发送新消息，确认没有继续下一次查阅，也没有把被打断的单元写成完成。
3. 跨会话或重启后查询关注，确认进度/配额保持；来源删除、版本变更或手动暂停后，旧关注不再被继续执行。
4. 连续进行倾诉→求建议→纠正理解→普通聊天，观察每轮表达是否切换、是否重复道歉；关闭dialogue_enabled后不继续旧模式。
5. 同一主人群私聊切换、其他人冒认主人、带无效message的工具请求，确认私聊模式与关注状态不会泄露。

自动化验证的是状态、权限和执行边界；自然程度仍需真实模型与QQ多轮对话验收。


## v0.16：普通聊天也能续接近况

在原有配置中打开 `[continuity] enabled=true`。保留 `auto_topics=true` 并开启 `[unified_mind] enabled=true, mode="active"`，才能从自然私聊整理近况；联系暂停、倾听短句不要求统一心智active。所有开关在源码默认配置中仍关闭，安装升级不替换实际私人设置。

例如：“我明天要考试，有点担心复习进度”可被整理成待续事项；相关话题或“我回来了”触发联想时最多自然带起一件，不盘问、不责怪缺席。后来“我已经考完了”经新原话核对后结束该话题；“不想再提……”可被核对为停止跟进。她不能把这段聊天说成亲眼看见考试，也不能宣称已经提醒或关心过。

| 完整私聊短句 | 立即生效的行为 |
| --- | --- |
| `先去忙`、`我先去忙了` | 暂停主动联系，默认3小时 |
| `晚安`、`我要睡了` | 暂停主动联系，默认8小时；正常回复仍可用 |
| `我回来了`、`忙完了` | 提前解除忙碌/休息的短暂停，不能撤销manual或永久拒绝 |
| `暂时不要主动联系我` 或 `/近况 暂停联系` | 持久暂停，直到明确恢复 |
| `/近况 暂停联系 2小时` | 定时暂停，支持1—72小时 |
| `今天不要主动联系我` | 暂停到配置时区次日零点，之后仍遵守免打扰和配额 |
| `可以主动联系我了` 或 `/近况 恢复联系` | 明确恢复本模块暂停，以及已启用Experience记录的拒绝；不会自动打开主动聊天或白名单 |
| `先听我说就好`、`我只想吐槽一下`、`我有点难过` | 两小时倾听偏好，不急着给建议，不记录诊断 |
| `帮我想想办法` 或 `/近况 建议` | 两小时建议偏好，结合具体事情提供帮助 |
| `/近况 正常`、`正常聊天吧` | 恢复普通表达 |

只有完整、可信主人私聊的明确短句直接改变状态；转发、群聊、自称、假设或引述不能设置。普通长句中的近况变动属于异步提取，需要模型核对；急需明确移除时可让她用 `living_world_continuity` 查询ID和版本，再由主人发送 `/近况 忘记 <话题ID> <当前版本>`。该命令清除这个近况的当前正文与对应审计正文、保留无正文的操作记录；依赖同一原始输入的其他近况也会失效。旧备份与其他独立记忆模块不因此被改写。

近况不是自动提醒授权，也不会生成执行计划。后台每批最多四条3—600字的可信纯文本，默认间隔5分钟、每天最多6批，每批最多两次共享预算的模型调用。空结果只需一次，失败计数，重启不重置。短句、无关内容、私密标识、预算不足或语义复核失败都可能不产生新近况；不能保证每句话都会被记下。待处理队列最多64条，满时只读工具可显示拥堵，过期未处理输入清掉原文。

只读工具支持 `query` 搜索与 `offset` 翻页，每页20条；原话也参与相关性检索，但不会被管理面板公开。已解决的话题只有收到解决之后的新消息，才可开启同名新一轮；明确停止跟进或遗忘的话题不会通过换个分类自动复活。

`auto_topics=false` 停止新增提取，已经验证的近况仍可读取；`enabled=false` 关闭本模块。近况、主人显式回忆、Brain/Mind和外部阅读共用统一联想与表达检查，群聊不会收到私聊原话。成长从受来源约束的原话学习，模型摘要不会变成自己的证据。

实际验收可补三组对话：先倾诉再明确求建议，观察表达切换；说去忙后重启容器，确认没有主动打扰而普通回复正常；留下一件待续事、换会话回来、说明完成并查询状态，确认没有把已解决的问题反复带起。模型自然程度仍需真实QQ验收。

后续产品方向是长期 AI 伴侣：同一个持续存在的角色、唯一主人、自己的兴趣与看法、能续接的共同经历，以及自然而有分寸的亲密表达。QQ群、私聊和外部平台都是同一个心智的信息窗口；来源与表达权限仍保留，不把群友的私事当成主人的关系素材。

v0.15.0 补上了明确的相处约定、纪念日与回忆账本、伴侣风格和真实时段提示。兴趣与观点继续由已有成长系统从证据中逐步形成，不把用户喜欢的东西直接当成她自己的喜好。没有关系积分、连续签到或因缺席扣分。

## 启用

先备份现有数据，再安装新 ZIP。不要用默认模板覆盖自己的数据库、QQ 与 MCP 配置。在现有配置中调整这些字段：

```toml
[owner]
enabled = true
# qq 沿用已绑定的主人 QQ；不要复制占位号码。
relationship_enabled = true
relationship_mode = "partner"

[unified_mind]
enabled = true
mode = "active"

[bond]
enabled = true
daily_rhythm = true
```

默认的 `brain_memory.include_owner=true` 让可信主人私聊进入统一上下文。若此前主动关闭了该项，需要在自己的输入名单中允许主人，否则读取工具与联想没有当前消息上下文。相处命令仍独立核验真实私聊发送者。

`owner.private_template` 非空时仍优先作为基础风格；已确认的禁用称呼和停止亲昵高于基础风格。`partner` 也不强制改掉麦麦原来的核心性格。旧版配置的 `banter` 不会在升级时悄悄改成伴侣。

兴趣与性格的持续学习另需开启已有 `[growth] enabled=true, mode="active"`，并保留真实消息或工具来源供它学习。阅读、共同计划、主动联系沿用各自开关。新增 `[bond]` 不会打开主动消息、联网、下载或额外模型调用；关系命令会持久写入，和阅读/计划一样不依赖主动聊天的 `general.dry_run`。

## 私聊中使用

必须是绑定主人本人发出的完整私聊消息。群聊、自称主人、转发组件、引述片段和模型工具参数均不能更改约定。

| 发送内容 | 效果 |
| --- | --- |
| `以后叫我小明吧` 或 `/相处 称呼 小明` | 保存日常称呼，换会话与重启后继续使用 |
| `别叫我主人` 或 `/相处 不叫 主人` | 禁用该称呼；绑定身份仍不变 |
| `/相处 称呼 默认` | 清除自定义称呼，回到配置中未被禁用的称呼 |
| `不要撒娇` 或 `/相处 亲昵 暂停` | 立即停止撒娇、暧昧和亲昵称呼，正常关心仍保留 |
| `/相处 亲昵 自然` | 允许自然亲昵，不要求每轮表达爱意 |
| `/相处 亲昵 默认` | 遵循已有关系风格 |
| `/相处 边界 不要拿我的旧昵称开玩笑` | 保存一条明确相处边界，仅用于私人表达 |
| `/相处 记住 我们约好周末讨论这本小说` | 保存主人自己留下的回忆，不自动创建提醒或把约定标成完成 |
| `/相处 纪念日 2026-11-05 初次相识` | 保存完整日期；当天聊天时可被联想，不主动群发祝福 |
| `/相处 删除边界 <边界key>` | 明确移除一条边界 |
| `/相处 忘记 <回忆ID> <当前版本>` | 停用回忆及其派生来源，保留变更审计 |

可问“看看我们保存的相处约定和回忆”，让 AI 使用只读 `living_world_relationship` 获取当前版本、边界 key 与回忆 ID。该工具可按 `query` 搜索、`offset` 翻页，每页最多 20 条；不能代主人确认或删除。普通长句暂不会自动变成长期约定，避免把玩笑、讨论或转述误写成承诺。称呼最多 24 字、边界 120 字、回忆 400 字；最多 20 个禁用称呼、20 条边界、200 条有效回忆。达到上限保留原数据，需要先明确删除旧项。

回忆仍标为主人自述。她可以说“你之前记下过……”，不能据此虚构自己亲身经历过线下约会。原始记录和派生结论经过统一表达判断，私聊回忆不直接进入群聊回复。遗忘指停用当前回忆、使相关引用失效，不抹去备份或审计历史。

纪念日只按配置时区和明确年月日匹配，不猜模糊日期，不自动把二月二十九日挪到二月二十八日。时段提示帮助语气自然，不推断你刚起床、在工作或该睡觉，也不虚构她吃饭、出门等线下生活。

## 实际验收

1. 私聊改称呼，切到新会话并重启容器，确认仍自然使用；再次说“别叫我主人”，不再把它当口癖。
2. 在伴侣风格下说“不要撒娇”，确认下一轮恢复正常聊天，不要求解释或反复确认。
3. 记下一件小事，隔天以相关话题提起；确认来源正确、不编造细节。用忘记命令停用后，再问时不能继续拿它当事实。
4. 群里与同一主人聊天，确认熟悉但不泄露私人昵称、约定或回忆；其他群友不能冒认主人。
5. 结合既有阅读和成长功能，看她是否能说出有依据的兴趣与不同看法，而不是复述“偏好强度+0.20”。
6. 保持几天不聊天后回来，不出现关系降级、指责或要求补偿；连续性来自保存的经历。
7. 查看管理面板的相处与回忆区域；做空目录备份恢复演练，确认原身份和约定还在。参见 [备份说明](BACKUP.md)。

自动化测试验证权限、状态连续性、来源失效和提示输入。实际聊天自然程度、MaiBot 容器兼容及模型表现，需要以上真实 QQ 对话验收。

## v0.20 她自己的有限项目

启用后，她可以从**已形成的自身兴趣**和相关的未解问题里选一件事持续查阅。只记住主人喜欢某个题目还不够；必须已有通过成长复核的兴趣和问题。每项分为取证、整理复核两阶段，保留暂停、完成、未解决或停止状态，跨会话/重启续接。

```toml
[projects]
enabled = true
interval_seconds = 900
max_daily_actions = 6
max_active_projects = 2
```

前提为唯一主人已配置、`unified_mind` 与 `growth` 都启用且为 `active`、MCP/Pixiv及记忆结果启用。查元信息还需 `mcp.research_enabled=true`；继续已有小说需 `reading.enabled=true` 和 `reading.auto_continue=true`。没有满足条件的兴趣/问题或来源时不自动编造任务。此项默认关闭，不自行打开新作品、下载或扩展外部操作权限。

她先继续与题目相关的已打开小说，或者查询本地 Pixiv 库并读取一项作品元信息；只有实际保存的原始内容能成为证据。下一阶段用两次模型调用整理并复核有限结论，计入原共享预算并保留前台额度。小说不当现实证据，标题/标签不当全文，资料不足保存“未解决”。成果经统一记忆的来源和听众判断后才参与回复，不把自己写的小结重新投入成长当新证据。

在主人私聊使用只读 `living_world_projects` 查看 ID、版本、阶段和状态；题目涉及他人私密内容或共读后文时不直接显示。主人可亲自发送完整指令：

```text
/项目 暂停 <项目ID> <版本>
/项目 继续 <项目ID> <版本>
/项目 停止 <项目ID> <版本>
```

模型和转发消息不能代发控制。停止后不再按同一问题自动重建；来源变化需重新核验，失效项目不能仅用继续指令绕过。历史最多32项、同时最多3项，默认2项；3次失败后暂停，14天到期停止。不开启无限任务队列，也不声称在后台一直思考。开启Attention时参与同一轮行动选择；关闭Attention时仍让位于新主人私聊，并避免项目和普通阅读同轮重复推进。

## v0.20 共同阅读进度

共读保存三件独立的事：她实际取回了哪些阅读单元、主人本人确认读到了哪里，以及哪一单元的引用确实发送给过主人。切换 QQ 会话或重启 Docker 容器后这些位置仍在；数据目录需沿用已有持久卷。取回正文不代表理解，工具准备讨论不代表已发送，成功发送也不代表主人已回答或双方聊完。

本功能默认关闭。在原配置中启用：

```toml
[shared_reading]
enabled = true
```

建立和查看共读还需已绑定唯一主人、启用统一心智并接收可信主人私聊；读取原作沿用 `[reading]`、`[mcp]` 和对应 cap/Pixiv 服务的原有开关与权限。这个开关不会自动打开联网、下载、后台阅读或主动聊天，也不新增模型调用。内部仍共用同一份知识，她可以继续独立阅读；对外表达受主人的共读边界限制。

先让她通过 `living_world_reading` 的 `open` 打开作品，再用 `next` 实际取回单元，使用 `list` 获取 `reading_id`。主人本人发送下列完整纯文本私聊命令；把 `<reading_id>` 替换成工具返回的整个 `reading:...` 标识，`<N>` 替换成非负整数：

| 命令 | 效果 |
| --- | --- |
| `/共读 开始 <reading_id>` | 绑定该来源版本，开始保护后文；不能据此认定主人已经读过 |
| `/共读 看到 <reading_id> <N>` | 主人确认自己的位置；允许回退，0 表示尚未确认读过 |
| `/共读 停止 <reading_id>` | 停止当前共读并保留位置，仍保护后文 |
| `/共读 清除 <reading_id>` | 停止共读，清零主人确认位置和已送达引用位置，仍保护后文 |
| `/共读 允许剧透 <reading_id>` | 主人明确解除这条绑定的作品保护 |
| `/共读 禁止剧透 <reading_id>` | 重新保护作品，不自动开始或推进共读 |

这里的小说“第 N 段”是插件已保存的第 N 个正文片段，底层位置为字符偏移；PDF 和插画是已保存的页序号，从 1 开始。它不是自动识别的章节号，也不一定对应阅读器的段落或纸质书页码。只能确认她已经实际取回、能够连续定位的单元；未知数量、尚未取回的页和“第几章”不会被猜成进度。单纯说“我读完了”、群聊、自称主人、转述、引用或 AI 工具参数都不能更新主人位置。

主人私聊可让她用 `living_world_shared_reading` 的 `list` 查看三个位置；其中 `ai_fetched_units` 是实际取回数，`owner_confirmed_units` 是主人确认数，`last_mentioned_unit` 是已成功发送引用到达过的最高单元号。`notes` 只返回确认范围内指定单元的原文与已经复核的笔记；`discuss` 准备指定单元的短引用。图像单元如果没有可核对的原文与已复核笔记，不会编造文字来讨论。普通阅读工具仍可推进她的实际阅读，受保护作品的返回仅含安全位置，标题作通用化处理。

`discuss` 返回的 `delivery_text` 必须原样作为独立整条消息发出，才有严格的回执匹配。草稿十分钟过期；失败发送、加前后缀、引用旧消息、群聊、其他收件人和无法核验目标的回执均不推进位置。自动选择下一段时不会不断重复已经提及的单元，明确指定单元仍可重谈。回退主人位置会使旧草稿失效，但不会抹去已经真实发送过的历史；需要清零两项共读位置时使用“清除”。“清除”不删除她自己的阅读游标、正文笔记、来源或防重放收据，也不改写旧备份；以后重新开始不会被旧命令和迟到回执自动恢复进度。

共读绑定具体作品、版本、来源引用及接入服务指纹。版本或来源变化、停用来源、关闭读取权限后，旧原文和草稿不可继续使用，禁剧透绑定仍保留；停止、清除或切到观察模式也不会自动解除保护。同一作品若存在多个版本的绑定，仍有任一条禁止剧透就继续保护。每位主人最多保存 64 条共读绑定，已停止和已清除的绑定仍占此上限。

防剧透限制实际作用于本插件已识别的受保护作品：原阅读返回、直接 MCP/图片读取、含作品 ID 的列表项，以及统一回复和主动聊天中能够追溯到该来源的原文与派生记忆。群聊也保守过滤这些来源，不能通过换群友发问绕开。内部学习不因此删除。保护不会清除宿主已经保留的聊天或工具上下文，也不能保证模型预训练知识、无可追踪来源的旧摘要、其他插件或同内容的未知来源绝不剧透；这不是对最终自然语言的全知语义过滤。关闭 `[shared_reading] enabled` 会关闭本模块保护，不能把它当作“仅暂停读取”。真实多轮验收见 [连续对话验收](EVALUATION.md)。

## v0.21 简短指代与话题承接

这项功能让“那件事”“后来呢”“继续说”有可追溯的承接对象。仅在可信主人私聊里，回复确实成功送达，而且能和本轮允许表达的原始记忆核对出至少 8 个有效字符的唯一逐字片段，才保存该话题引用。只检索到候选、内部想过、准备回复或发送失败，都不算实际提及。同一回复在 90 秒有效窗口内分段发送时，合并各段实际提及的来源；多话题仍先澄清，不只记第一段。不会保存整个聊天或隐藏思考过程，也不会因为提及而认定主人同意或事情已经有结果。

```toml
[reference]
enabled = true
ttl_hours = 24
```

默认关闭，需要唯一主人、统一心智启用且为 `active`。时效可设 1–72 小时，从最近实际核验的提及时间开始算；普通问候、追问或重启不延长时效，调短配置立即按较短范围核验。沿用原持久卷或数据库时，焦点可以跨会话及重启读取；新会话仍需先接收可信主人消息建立身份上下文。

当前只识别有限的简短**整句**，可带末尾标点，例如“那件事”“那件事呢”“那个呢”“这个呢”“后来呢”“然后呢”“继续”“继续说”“继续讲”“接着说吧”“后来怎么样”“上次那件事”“我们刚才说到哪了”。完整的新问题照常检索；没有依据时不把含有这些词的长句强行解释成旧话题。同一次已发送回复涉及多个原始来源时先澄清，不默认挑最新一条；来源过期、改变、不可表达或受共读边界限制时也先问清。只有一个有效焦点时，检索优先承接那个原始来源及其直接派生内容，原始用户请求和当前沟通意图不改写。

明确新话题会清空旧焦点，“我回来了”“你好”“谢谢”等完整问候和回应保留原到期时间。图片、语音和未知非文本内容会中断旧的发送匹配，并暂停原焦点的承接资格。之后说“那个呢”需先澄清，防止把图片的新对象误认成旧事。“换个话题”“先不聊这个了”取消当前承接，其他普通命令只中断匹配。v0.26 起，主人私聊完整发送 `/话题 清除` 会一并清除历史提及，保留原始记忆。只读 `living_world_reference` 可查看当前是否仍有可用来源和时效。

逐字核验有意保守：模型改写、缩写或只说“加油”时，可能没有足够依据建立焦点，之后会要求说清是哪件事。本功能不承诺理解任意代词或自动重建所有聊天上下文；不增加模型调用，最终表达仍走原有听众判断与共读限制。
