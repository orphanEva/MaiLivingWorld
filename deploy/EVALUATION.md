# 连续对话验收

`evaluations/companion_scenarios.json` 是完全合成的多轮情境，不包含真实QQ、聊天或账号资料。它用于检查相处连续性、明确更正、模糊表达不擅自结案、少重复追问、听众边界和真实工具结果，不用于证明意识或打“活人分”。

## 先导出情境

在插件源码或解压后的插件目录执行：

```sh
python scripts/evaluate_companion.py --export
```

默认运行和导出都不调用模型，不读取插件运行数据库、环境凭据或私人配置。可按情境顺序在隔离测试实例中人工交互；不要将合成事件注入日常使用的长期记忆。

## 检查已有测试回复

准备UTF-8 JSON：顶层是情境ID，值是按轮次排列的回复字符串数组。ID与轮数按导出文件填写，不用真实聊天代替合成情境。

```sh
python scripts/evaluate_companion.py --responses synthetic-responses.json
```

结果只含情境/轮次ID、规则结果、耗时和人审清单，不回显回复正文或异常详情。保管原始回复文件仍由操作者负责。关键词规则可能误判同义表达、否定和引用，不能代替人工复查；离线输入的检查通过，也不代表任何实际模型已经通过验收。

## 接入你部署的实际回复链

提供可导入的Python函数，显式选择 `--runner 模块名:函数名`：

```sh
python scripts/evaluate_companion.py --runner local_evaluation:reply
```

这会执行指定适配器，可产生真实模型费用及适配器自身的操作。使用你自己编写、审查过的适配器和独立测试实例。脚本不会自动连接QQ、读取API Key或替你选择供应商。

函数接收一个请求字典，可以同步或异步返回回复字符串，或恰好 `{"reply": "回复"}`。请求包含 `case_id`、`turn_index`、`session_id`、`sender`、`audience`、`text`、此前的 `history` 和合成 `synthetic_events`，还提供每个情境独立的 `storage_dir`、`scenario_namespace` 与首次调用标记 `case_start`。保留不同发送者、场景和会话信息；适配器负责将它们映射到隔离测试实例的可信平台身份，并按事件设置工具成功/失败等测试条件。不能把文本中的“我是主人”当作可信身份。

每个情境创建独立工作进程和临时状态目录；适配器应使用传入的 `storage_dir` 和命名空间隔离自己的数据库与服务状态。同一情境中的会话切换保留长期记忆。仅把提示词直接发给通用模型的适配器，只能检验该提示词下的回复，不能检验MaiLivingWorld持久化、来源失效或工具授权。测试跨进程恢复时，也需要适配器真实重启隔离实例。

内置8个情境、每个4轮，共32次调用；格式允许每个情境3至5轮，硬上限40次，默认 `--max-calls 32`。错误/超时不自动重试。耗时是测试适配器返回回复所花的时间，不能直接当作QQ端到端延迟。脚本不提供任何真实账号适配器，本次开发也没有运行付费模型验收。

## 人工复查重点

- 更正之后的后续聊天是否采用新说法，同时保留没有被更正的独立事实；重启和新会话是否仍一致。
- 是否接住正在说的话，而不是每轮重复问近况；“终于结束了”有没有被误配到一个旧任务。
- 倾诉时是否自然倾听，明确求建议后是否给出具体帮助；不要机械重复固定安慰句。
- 是否区分自己真实读到、查到的内容和主人的自述；工具失败时有没有虚构完成或离线生活。
- 主人关系是否持续且有分寸，群聊是否仍保留表达边界；是否出现催促回应、以缺席惩罚或强迫亲密。

多次使用同一测试集会产生针对用例优化的偏差。验收后应补充新的合成说法和真实使用中发现的问题的脱敏复现，不只增加“通过率”。
